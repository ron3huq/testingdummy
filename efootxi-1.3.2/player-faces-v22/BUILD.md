# V22 build and validation

Baseline: published v21 main ZIP, SHA256 `5b8065ff4f2d2cb32deaa77f669a839c7469cfce84134ee8e8790b4e216fed4f`. The v21 container must be extracted into `../player-faces-v21/container/` before building. Its reports and reader logs are inputs to the incremental asset builder. Native engine references and UEViewer live in `/workspace/ronaldo-work/`; these large dependencies are not embedded in this source archive. Python dependencies: numpy, Pillow, scipy, cityhash, etcpak, texture2ddecoder, pyelftools, unicorn, ziglang 0.13.0. Helpers copied from v21 retain their original provenance.

`source/build_assets.py` modifies only two lower-face weight fields and four mini textures in the baseline; adds one test mesh with literal ND06 skin MIC imports and eight native Ex atlases. Minimal font references and their package-store entries are in `references/`; the RGBA mini sheet is in `art/`. Original four failing head assets, large portraits/backgrounds, ordinary A–Z fonts and other established assets are byte identical. Build outputs go to `container/`.

Run `sh source/build_native.sh` in the configured Python environment. **draw_probe.inc is a required compiler input.** Native uses no libc imports. Build script pins the SO digest in `noodle_hair.py`. Probe reads root, attachment, face and stencil component arrays at reflected offsets; it never disables or replaces a component. Material queries are restricted to components proven to contain the mesh delivered by the callback. Sampling is throttled to every 256 bake calls per actor; stable copied strings are published under a lock and guarded by an odd/even generation counter. Python reconstructs old u64 counters from explicit u32 halves to avoid the phone bridge's observed signed32 reporting truncation.

Tests: `verify_assets.py` uses `/workspace/ronaldo-work/v22-reader` with native bundles plus this completed container and independent UEViewer exports. `validate_probe.py` includes the 578 baseline native checks and models engine query bodies; it does not model an Android renderer. `validate_squad_abi.py` executes actual engine prologue/argument-read instructions; `validate_install.py` tests 15 hook installation paths. `validate_runtime.py` checks the staged `source/deploy/` tree; `package_release.py` produces the complete install ZIP and source ZIP. Stage eight work files from the pinned v21 ZIP, replace runtime/SO/bundle metadata and the three container files; do not ship My League personal configuration files.

Reports explicitly keep `phone_tested` and `black_faces_fixed_verified` false. The material control affects only test ID 105807861630781. The correct next evidence is the v22 phone log with `head_draw_probes` and the observed test-card color, not the existence of a hook or non-null callback alone.
