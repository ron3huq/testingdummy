# Evidence, intervention, limits

The user explicitly confirmed that the four originally failing card IDs became nonblack after the v17 comparison redirected them to the working ND06 head. This was clarified to exclude the misleading case of only viewing the original 2006 card. It narrows investigation to the original private head asset/material interaction. It does not prove a specific shader, texture or geometry defect.

V18 rebases the four private asset stacks onto the actual working ND06 templates: mesh serialized prefix and static face MICs, and face Texture2D serialized headers. Ten mesh variants are published under fresh NV01/NV27/NVJR/NVHD namespaces. It preserves the original four complete LOD records literally, not re-quantized equivalent weights. Reference skeleton and bind transforms are byte-identical to the source. Texture platform/mip payloads and ubulk chunks are copied from each original face, not from the 2006 portrait. Diffuse PNG readback matches the original four source exports exactly. All existing hair assets and 209 retained chunks remain unchanged. No new shader bytecode is generated. The runtime keeps static source MICs instead of the failed MID experiment; all target IDs and source Face IDs are preserved. This is a candidate device repair, not a renderer-verified conclusion.

Lowercase jersey failure was traced to the original glyph metrics: glyph resolver0x39259c8 searches the native character table at0xc4193c; the requested lowercase letters have no entries. Hence Xuan Son reduced to XS. The user then explicitly chose uppercase full jersey names to preserve the original per-kit fonts and sizing. Tests execute original glyph resolver code on every letter of all eight uppercase names. No font asset or layout parameter is modified, and the original font resource configuration/key is forwarded unchanged.

Native no-club semantics are proven by the original importer0x824c57c..0x824c5c4: missing wire team ID selects constant0xc77ae8 (0xffffffff), then calls setter0x8257844(record,const uint32*) which writes record+0x140. V18 uses that same setter/value for only six exact Vietnam card records, after decoded typed64 identity validation. Country remains38 (Vietnam); IShowSpeed/Jr remain228 (Portugal), with their club fields untouched. Whole-record comparisons verify adjacent fields, stats, identities and the other cards stay intact. It does not edit team member arrays or owned/save data. UI club-emblem behavior remains a phone validation item.

The latest core tests contain680 applicable cases. The previous MID-specific tests were removed because v18 deliberately no longer creates MIDs. The original native no-club setter, country setter/getter and glyph metrics execute; engine allocation/render/virtual boundaries remain modeled. No Android renderer, driver or device session runs here. Keep `device_verified=false` and do not infer visual correctness from hook/material counters.
